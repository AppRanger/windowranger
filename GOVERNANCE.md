# WindowRanger governance

WindowRanger is currently a single-maintainer project. Chris Hobden (`@VeniVidiVici`) is the
maintainer and final decision-maker for project scope, architecture, releases, moderation, and
repository access.

## How decisions are made

- Small fixes and documentation changes are decided through pull-request review.
- Features, broad refactors, persistence changes, new dependencies, and changes to window-management
  semantics should be discussed in an issue before implementation.
- The maintainer weighs user safety, privacy, accessibility, product coherence, maintenance cost,
  and evidence from tests and live validation.
- A merged pull request records the accepted decision. Design notes may be added for decisions that
  need a longer-lived rationale.
- The maintainer may decline a technically sound contribution when it conflicts with the project's
  scope, safety boundaries, or maintenance capacity.

## Roles

Contributors may report issues, propose designs, submit pull requests, review changes, and improve
documentation. Repeated, constructive participation may lead to triage or commit access at the
maintainer's discretion. No additional formal project roles exist yet.

Repository access does not by itself grant release authority. Publishing, signing, notarisation,
distribution, and security disclosures require explicit maintainer approval.

## Changing governance

This document should be updated as the contributor base grows. Material governance changes will be
proposed publicly and recorded in the repository before taking effect.
