# WindowRanger 1.0.2

WindowRanger 1.0.2 makes tiled window movement more natural, supports dragging windows between
displays regardless of layout, and fixes two first-launch menu bar issues.

## Improved

- Tiled windows now use a clear directional insertion preview while dragging, so moving a window
  changes the BSP tree where it is dropped instead of only swapping two existing positions.
- Windows can be dragged between displays in any combination of Tiled, Accordion, and Freeform
  layouts. Transfers preserve the destination layout's normal placement behaviour and work in both
  Independent Displays and Unified workspace modes.

## Fixed

- Fixed menu bar text initially using the wrong colour until the first workspace switch.
- Fixed the WindowRanger status menu initially appearing too high and then jumping into position
  when the pointer entered it.
- Fixed cross-display drags snapping back to the source display or becoming jumpy while moving from
  Accordion or Freeform layouts.

## Requirements

- macOS 14 or later.
- Accessibility permission for window discovery and management.
- Screen Recording permission only when optional captured workspace previews are enabled.

## Installation

Download `WindowRanger-1.0.2.dmg` from this release's **Assets** section, open it, and drag
WindowRanger onto the Applications shortcut. The notarized ZIP and both checksum files are included
as fallbacks and for verification.

Homebrew users can install or upgrade the public Stable Cask with:

```sh
brew install --cask appranger/tap/windowranger
brew upgrade --cask appranger/tap/windowranger
```

Stable 1.0.0 and 1.0.1 users can also install this update through WindowRanger's signed in-app
updater once the 1.0.2 feed is published.

## Known limitations

- WindowRanger manages virtual workspaces inside the current macOS desktop; it does not replace
  native macOS Spaces.
- Captured workspace previews remain optional and off by default.
- Some applications expose ambiguous or read-only Accessibility windows that WindowRanger
  conservatively ignores.

## Feedback and security

Use the repository issue forms for privacy-safe bugs, feature requests, and questions. Do not post
suspected vulnerabilities, private diagnostics, window titles, document names, URLs, or user file
paths in a public issue; follow `SECURITY.md` instead.
