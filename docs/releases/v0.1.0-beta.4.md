# WindowRanger 0.1.0 Beta 4

> This is pre-release software. Back up important work and use **Quit WindowRanger** before
> replacing an existing build.

Beta 4 focuses on window-lifecycle reliability after restart and around transient application UI.

## Highlights

- Confirmation prompts and other explicit dialogs that temporarily appear on a nonstandard window
  layer are left untouched until their metadata settles. If a fixed-size surface rejects its
  requested resize, WindowRanger no longer moves it toward a layout frame it cannot occupy.
- A configured Quick App now follows an unambiguous same-process native-tab replacement and is
  claimed before initial workspace layout after WindowRanger restarts. Visible Quick Apps return
  directly to their presentation instead of briefly joining the current workspace.
- Workspace app cycling can reach an inactive managed standard window immediately after restart
  when macOS temporarily reports a negative window layer but still exposes a writable exact-focus
  route. Dialogs, overlays, parked windows, and ambiguous read-only surfaces remain excluded.

## Requirements

- macOS 14 or later.
- Accessibility permission for window discovery and management.

## Installation

1. Download `WindowRanger-0.1.0-beta.4.dmg` from this release's **Assets** section.
2. Optionally verify it against `WindowRanger-0.1.0-beta.4.dmg.sha256`.
3. Use **Quit WindowRanger** in the existing copy, then open the DMG.
4. Drag `WindowRanger.app` onto the Applications shortcut and replace the existing copy when Finder
   asks.
5. Launch WindowRanger from `/Applications`. If macOS asks again, grant Accessibility access to
   `dev.appranger.WindowRanger`.

The notarized ZIP and its checksum are included as a fallback for environments that cannot mount a
DMG. GitHub's automatically generated source archives do not contain the installable application.

## Known limitations

- The complete manual regression, accessibility, privacy, clean-user, and clean-machine matrices
  remain in progress.
- Quick App still deliberately refuses ambiguous multi-window targets and does not launch an
  application that is not already running. Broader two-profile validation remains open.
- The Command Wheel workspace-action icon family is functional but still has a deferred systematic
  SF Symbols review.
- Trackpad workspace swiping is off by default and depends on macOS exposing the generic gesture
  stream. System gestures may take precedence.
- Sparkle automatic updates are not included yet; install newer builds manually.
- WindowRanger does not integrate with native macOS Spaces.
- Quit other window managers that use overlapping global shortcuts before testing WindowRanger.

## Feedback and security

Use the repository issue forms for privacy-safe bugs, feature requests, and questions. Do not post
suspected vulnerabilities, private diagnostics, window titles, document names, URLs, or user file
paths in a public issue; follow `SECURITY.md` instead.
